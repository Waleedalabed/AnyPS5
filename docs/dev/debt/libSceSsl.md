Trusted authorities are the context's `sceSslLoadCert` CAs plus the host's root store (the system bundle on Linux, the `ROOT` store on Windows) in place of the console's built-in roots, which are not shipped. Disabling an option ignores the matching Mbed TLS verification failure; any other failure is kept. The console's error codes are unknown for an unknown connection, a terminated context, a null host, an unknown option, flag or version, option changes after the handshake, a rejected certificate, a failed handshake and a transport error, so all of these throw. A verification callback set before `sceSslConnect` makes it throw `NotImplemented_nid_no_patch`, as the layout of the verification bits passed to it is unknown. Without the partial flag a read fills the buffer unless the peer closes; the peer's close notification reads as 0. A peek keeps the bytes for the next read. `sceSslClose` sends the close notification and ends the session; the connection then refuses reads and writes until `sceSslDeleteConnection`. `sceSslGetAlpnSelected` returns null before a handshake and when no protocol was agreed. `sceSslTerm` leaves the context's connections to `sceSslDeleteConnection`; a started session keeps the context's pool alive

CA queries return independently owned snapshots; unload clears active credentials while outstanding snapshots remain valid. Appending repeated CA imports, snapshot lifetime across unload, memory overhead and error precedence have not been measured on a PS5. Invalid loads, malformed material, exhausted pools and unsupported keys throw rather than inventing console error codes. No root bundle is shipped; an empty context still returns `NOT_FOUND`. The existing null-list error, unknown-context behavior and legacy clearing of foreign raw CA lists remain unchanged.
